# Content and performance-time evidence

V1.1.0 includes evidence-based performance mapping and experimental local audio candidates, without a calibrated automatic accuracy claim. No model weights or new dependencies are installed automatically. `analyze-audio` needs explicitly selected existing Python with NumPy and FFmpeg. The FFT/chroma DTW adapter returns `needs_review` for every result; it does not diagnose arrangement differences reliably or certify dense chords. Full repeat/arrangement recognition and automatic calibrated note verification remain experimental, not implemented production promises.

## Commands

1. `score check --musicxml SCORE --out DIR` retains the existing structural check. Keep original PDF/image and reviewed XML separate; a re-arranged XML is not ground truth.
2. `symbolic --check CHECK --out EVENTS [--playback ORDER]` creates `piano-symbolic-events/v2`. ORDER is an object mapping each part to its explicit measure-ID sequence. Repeated measures get distinct occurrence IDs; no automatic jump expansion. Rest events are retained, ties and slurs are separate. Existing unsupported interpretation cases still stop.
For MIDI use `symbolic --midi FILE --assignment FILE --out EVENTS`. Assignment has `lanes` mapping each `track:channel` to `part`, `voice`, positive `staff`, and `noteMeasures` mapping every parsed note index to a reviewed measure ID. A track is never silently treated as one measure. The generated companion `.check.json` is used by quality instead of an XML structural report. Existing MIDI tempo-map seconds remain available in the parsed report; the performance map remains separate. Sharp pitch names are a display convention, not recovered original enharmonic spelling. No invented rests or meter; no default pitch-based hand split.

3. `analyze-audio --python EXISTING_PYTHON --audio MASTER --events EVENTS --bpm NOMINAL --out CANDIDATE` proposes pitch/chroma evidence, constrained coarse DTW, short-window attack candidates and a monotone attack-group edit path. Final candidate anchors use the attack path when available; coarseDtwAnchors remain separately visible. Unmatched beats/attacks indicate doubts, not certified deletions/insertions. Positive nominal BPM initializes the coarse reference, not final timing. Hard caps: ten minutes decoded audio, four million coarse DTW cells and one million attack edit cells; split explicitly when exceeded. FFT resolution, harmonics, tuning, pedal, soft/legato attacks and low voices are limitations. No dependency downloads.
4. Make a separately reviewed `piano-time-map/v2`: `scoreSha256`, `audioSha256`, and `anchors` with strictly increasing `beat`, `seconds`, `method` (`manual`/`observed`) and actual `evidenceRef`. At least two anchors cover all starts/ends. Candidate/interpolated anchors are rejected by this interface. The user/reviewer must establish real anchors; do not rename DTW suggestions as measurements.
5. `map-time --events EVENTS --map MAP --audio MASTER --placement PLACEMENT --out TIMELINE [--fps 30]`. Placement supplies scoreWidth/scoreHeight, notes `{id,x,y}` (occurrence or written IDs), and handMap keyed `part:staff:voice`. All starts and ends use the piecewise map; intermediate boundaries are marked interpolated. This is not measured pedal/note-off. Tied spans stay contiguous. Re-measure geometry with existing `geometry` after producing the timeline.
6. `quality --timeline TIMELINE --audio MASTER --quality PACKET --out RESULT` recomputes content/timing gates from the review, never accepts a summary `passed` flag. `bind --quality PACKET --production CONFIG ...` repeats the evaluation. Silence does not claim audio correspondence; drafts remain drafts.

## Quality packet

PACKET contains `check` (the original structural report) and `review` (`piano-quality-review/v2`). Review binds `scoreSha256`, `audioSha256`, `mapSha256` (canonical object hash), `checkSha256`, actual `actor:'user'`, `messageRef`, `message`, and `fingerprints` mapping real evidence filenames to SHA256. Local JSON is not identity authentication; only record a real user response. Synthetic test actors must never be used for a real song.

`source:{status:'reviewed',sourceSha256,originalSourceSha256,evidenceRef}` records independent source comparison; actual checked MusicXML/MIDI bytes must also be in fingerprints. Include original PDF, per-measure crops and their review when the source was PDF. For formal PDF/image jobs the packet also contains `sourceScope:{source,inventory,selection?}`; the inventory and scope are recomputed against the actual bound original, never accepted as a passed summary. `structure:{status:'matched',extraNotesChecked:true,evidenceRef}` covers full excerpt scope, order, repeats and unexpected notes. Do not use a synthesized reference from the XML as independent PDF proof.

`notes` contains exactly one item per pitched written occurrence: `id`, `pitch`, `pitchStatus:'matched'`, `timingStatus:'observed'`, `observedSeconds`, `uncertaintySeconds`, `evidenceRef`. Require independent annotated audio/score comparison. Coverage must be 100%; uncertainty over one frame, any residual over two frames, median residual over one frame, unresolved or missing notes blocks formal output. Tied continuations require `timingStatus:'reviewed-tie-boundary'`; they are not new audible attacks. Record unresolved ties instead of inventing onsets. This validates attacks/reviewed tied boundaries; mapped note ends are notation interpolation, not measured key release or pedal. `unresolved` blocks export. No numeric confidence substitutes for review.

## Original scope and review worksheet

`source-scope --source PDF --inventory INVENTORY --check CHECK --out RESULT [--selection SELECTION]` verifies an inventory with schema `piano-source-inventory/v1`, original `sourceSha256`, positive `measureCount`, observer and real crop/page `fingerprints`. Optional tempoBpm is diagnostic. Full score is the default. A selection uses `{scope:'excerpt',reason,messageRef,mapping:[{xmlMeasureId,sourceMeasure}]}` with every primary-part non-pickup measure mapped. Identical counts or accepted scope never establish pitch truth. The inventory is inspected evidence, not automatic OMR.

`quality-request --timeline TIMELINE --check CHECK --audio AUDIO --source ORIGINAL --checked-source XML --source-scope SCOPE_PACKET --out DIR` creates a local review page and blank packet. Alternatively use `--candidate ANALYSIS --events EVENTS` instead of timeline to begin independent observation before a reviewed map exists. That mode deliberately has mapSha256=null and an unresolved blocker: establish real anchors, rebuild the mapped timeline, regenerate the final request and retain the observations as frozen evidence. Never copy candidate seconds into the observation column. No action on the page silently approves score/keyframes or bypasses content gates. `quality ... --source ORIGINAL` enables the same original scope check for standalone evaluation; bind derives the source hash from the score review automatically.

The conservative first version requires complete human evidence; automatic FFT output cannot satisfy this packet. It can still help locate doubts and propose timing. This is deliberately an abstaining baseline until frozen negative/positive experiments support a calibrated automatic adapter. Human-reviewed results say passed_within_scope with accuracyCertified=false, not a universal accuracy percentage.

New jobs freeze configuration, quality packet, underlying evidence, reachable local entry/component imports, package/lock/config files and Skill analysis scripts. Changing these invalidates the job. New formal render rejects legacy jobs without this evidence. Preview of historical material remains available. Output audio checks compare decoded master samples against rendered audio; they do not re-certify content from three energy peaks. Keep full-song risk review in addition to the first-four pilot.

## Experiment discipline

Freeze the original PDF, MP3 and XML independently. A rearranged XML and a fixed-BPM timeline are candidate inputs, not correctness labels. Start with independent source comparisons and hidden audio timestamps. Record normal controls, pitch/octave/chord mutations, missing/reordered/repeated sections, local shifts and tempo drift; preserve known modifications and split development/acceptance by passage. Count error localization, abstention and false release separately. No ground truth means not_run, not passed; do not fabricate listening approval, note accuracy or a benchmark from a model reading twice. Keep all private fixtures and internal test reports outside the distributable Skill.
