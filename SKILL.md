# Piano Remotion — RC5 remediation

Read the installed official `remotion-best-practices` first and follow its relevant preview/render guidance. Reuse it; if missing, report the official installation plan before a first installation. The official Agent Skill and Remotion runtime dependencies are separate. Never upgrade pinned dependencies merely because new guidance exists.

Preserve the byte-identical ScoreNoteLeap, PianoRemotion alias and PianoScoreScene. Do not simplify the two-hand leaps, glow trails, highlights or shared camera transform, or touch private song assets. Personal overlays stay off unless explicitly authorized. Publication does not assign a public license; see LICENSE.txt.

## One execution entry for every Agent

Use `node <skill>/scripts/piano.mjs <command>` for all new song work. Read [the RC5 workflow](references/rc5-workflow.md) before executing. Node and matching Remotion dependencies are required; Python is optional for the base animation and only needed for score/XML/PDF tasks that use it. Do not create a Python environment by default.

1. **Audit and reuse.** Run doctor with the current project and explicit --authorized-project roots, and existing --python paths when known. Check actual module/CLI usability, versions, Node package managers, project/authorized virtual environments, PATH and bounded standard locations. Not on PATH does not mean not installed. Prefer current compatible dependencies, then compatible authorized projects. Do not link incompatible or replace existing node_modules.
2. **Plan missing installs.** Use install --plan. Before first dependency installation or adding large packages/models, report exact paths/versions/content/reason and request confirmation. Scripts never run npm or create a venv automatically. Existing authorization covers only the stated scope, not unrelated installations. Scaffolding and confirmation_required are not proof of installed dependencies.
3. **Classify materials.** Distinguish MusicXML, MIDI, SVG/timeline, MP3, PDF, staff images and jianpu. Reuse reliable standard data before recognition. For PDF/staff images prefer already installed professional OMR; if unavailable, return the concrete missing capability and optional verified installation/alternative. Reuse an Agent's existing libraries/Skills where appropriate, but execute parsing and validation through scripts. Do not treat VexFlow/MuseScore output as proof of recognition.
4. **Review the score before layout completion.** Use score source/check/compare; preserve pitch/rhythm/meter/rest/chord/staff/tie doubts. Generate original-versus-reflow measure crops and review evidence. Structure passing is separate from visual approval. Any unresolved differences or stale hashes block final approval. See [score validation](references/score-validation.md) and [source routing](references/material-preparation.md).
5. **Bind one layout.** SVG and timeline must be produced by the same actual engraving run. Bind producer/run IDs, file hashes and every mapped notehead. Current checked geometry supports normalized ellipse/circle anchors; complex path/transform layouts require a verified adapter and must not be guessed. See [the data contract](references/data-contract.md).
6. **Require an audio decision.** If MP3 is supplied, probe/decode it, check duration/audibility and run align. If absent, ask whether to synthesize piano-like audio or explicitly preview silently. Synthesis requires consent and actual pitches. No default silent output may be called a completed audible work.
7. **Freeze the real song.** bind produces a checked job from explicit props, score/audio/timeline/layout and review/calibration evidence. Use that SAME job for preview/render. The separate Song entry has no Demo fallback. Changed input fingerprints invalidate it. Existing Demo commands are legacy compatibility tools, not an escape from checked-song gates.
8. **Verify export.** Only the current user's export instruction authorizes render --confirmed. The script checks MP4 video/audio streams, duration/fps/dimensions, decoded non-silent audio and sampled beginning/middle/end onset offsets. View representative frames too. `media_verified` is not full music recognition certification. Report each gate independently with actual artifacts, offsets, errors and unresolved work.

Use [installation/usage](README_使用说明.md) and [copyable prompts](examples/agent-prompts.md) when helping users start. Built-in tests are synthetic and do not certify all real PDFs, recordings, WorkBuddy installations or other operating systems. Do not convert missing tools, recognition uncertainty, visual differences or failed audio alignment into an invented pass.
